# Batch 29: One research workspace, evidence-based statement locator

The single top-of-page form supports two tasks: **research a medical topic**
and **find a statement in papers**. Research analysis choices are **Public evidence**
and **administrator-authorized DeepSeek AI**. Statement lookup is administrator-only.
No password or token is stored by the UI, no token is placed in a URL, and the
existing backend quota and single-active-job lock remain the only job gate.

## The same result tabs reflect the same execution

- **Overview:** search summary, source paper count, model-call count.
- **Research papers:** actual PubMed references and available source snippets.
- **PICO evidence:** source-anchored lexical candidates for live public
  abstracts or DeepSeek's mechanically verified candidates in AI research.
  A statement lookup shows the matched passage and location here.
- **Agent workflow:** truthful software-vs-DeepSeek stages, actual model HTTP
  requests and elapsed time. This is not six independent LLMs.

## Claim locator evidence method

1. DeepSeek interprets the statement as a short English biomedical literature
   query. An optional explicit PMID can restrict inspection to one paper.
2. Up to five actual PubMed records are selected, excluding the held-out
   evaluation set. Authors and titles are read from NCBI EFetch XML, *not*
   generated by DeepSeek.
3. Accessible PubMed abstracts and where available Europe PMC official REST
   full-text XML are screened. The papers' text is source data, not model
   instructions. DeepSeek selects identifiers for relevant candidate passages.
4. Only passage identifiers that exist in the retrieved text are accepted.
   The UI distinguishes literal phrase matches from **related discussion**.
   It does NOT infer that a paper supports or proves the asserted claim.
5. For eligible PMC open-access papers, the 2026 PMC Cloud Service on AWS is
   consulted for a PDF. The program extracts up to 30 PDF pages using
   `pdftotext` (if installed) or `pypdf` (if available in the app environment).
   A PDF viewer page number is returned **only** if the normalized excerpt is
   found verbatim on that page. No journal page ranges or section positions
   are passed off as verified page numbers. Missing PDF, text extraction,
   page position or licensing access yields **Page number unavailable**.
6. Return up to five matching papers, with the source title, indexed authors,
   PubMed link, short source excerpt, section, and verified PDF viewer page
   where available. No-match results mean *not found in the material searched*,
   not proof of absence across the biomedical literature.

## Important limits

- This is a source location/relevance prototype, **not** a clinical claim
  truth checker. Clinical facts and Bengali output quality have no gold-label
  evaluation at this stage.
- A general search is limited to five retrieved papers, so **absence cannot
  be established**. Not every PubMed paper offers accessible full text, and
  even public OA PDFs are not always extractable or page-numbered.
- Evidence-only public searches can serve several browsers (the new endpoint
  is bounded to three concurrent requests). DeepSeek remains one active job at
  a time across both research and claim flows, reusing the existing hourly
  quota and CPU/RAM-constrained local container.
- The script changes only BanglaMedScanner source and dedicated app runtime.
  ERP, n8n, Traefik, Nginx, global Python installations, and the model
  container must remain untouched.

## Source interfaces

- NCBI Entrez EFetch: `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi`
- Europe PMC REST fullTextXML: `https://www.ebi.ac.uk/europepmc/webservices/rest/{pmcid}/fullTextXML`
- Official 2026 PMC Cloud article dataset:
  `https://pmc-oa-opendata.s3.amazonaws.com/README.txt`

The former NCBI OA FTP service / OA Web Service was retired in 2026.
